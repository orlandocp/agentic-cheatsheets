# Structure rules

The reader is a newcomer. The sheet is read top to bottom once, then consulted by section.

## Section order
Keep this order. Drop a section that does not apply; do not reorder.

| # | Id | Section | Content |
|---|---|---|---|
| 0 | `start` | Before you start | The central idea (why the topic exists), then vocabulary cards in dependency order. |
| 1 | `basics` | Basics | The core concepts, each with an analogy and its purpose. |
| 2 | `compare` | Comparison | Side-by-side table of the core concepts. |
| 3 | `variants` | Variants | One line per variant, grouped in families. Then diagrams and a matrix of what each one gets and returns. A box for any confusing name. |
| 4 | `cards` | Cards | One card per variant, same order and fields. |
| 5 | `choose` | How to choose | Decision ladder. |
| 6 | `write` | How it is written | Annotated examples, locations, full field tables. |
| 7 | `combine` | Combining | Patterns that use several variants together. |
| 8 | `limits` | Limits and defaults | Value, default and how to change it. |
| 9 | `mistakes` | Common mistakes | Wrong, then better. |
| 10 | `glossary` | Glossary | Every term, alphabetical, plus official sources. |

## Rules
- Define a term before its first use, in section 0 or inline in plain words.
- A collapsible block is never the only place a term is defined.
- Each variant has one canonical name and number. Use them identically everywhere: map, diagrams,
  matrix, cards, ladder, mistakes, glossary.
- Group variants in at most 4 families, one color each.
- Numbering schemes never collide: numbers for variants, letters for ladder questions, no numbers
  for priority lists.
- Cards share the same fields in the same order, such as "Sees", "Use it", "Avoid it", "How",
  "Watch out".
- The lead sentence of each card defines the variant on its own, because it is the tooltip text.
- A definition never contradicts another place. If one place is narrower, widen it.
- Every term defined anywhere has a glossary entry.
- Cross-references ("section 6", "variant 2", "the example in section 6") point to the right place.
- An example must match its label. Do not use a variant-2 example to illustrate variant 1.
- When the docs do not say something the reader would ask, write "the documentation does not say …".
